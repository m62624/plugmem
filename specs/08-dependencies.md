> Зафиксировано 2026-07-17 по фактическому состоянию crates.io (`cargo search`)
> и **реальными пробными сборками** под `wasm32v1-none` (toolchain
> rustc/cargo 1.96.0). Не по памяти. Методика проверки — внизу; она же
> обязательна для любой будущей новой зависимости ядра.

Цена unicode-таблиц в wasm-бинаре измерена минимальным cdylib-пробником
(`no_std`, только `Tokenizer`, `opt-level = "z"` + lto + strip,
`wasm32v1-none`): **163 КиБ** — сюда входят таблицы сегментации, NFKC и
lowercase (последние были нужны и токенизатору v1). ~16% бюджета артефакта
1 МиБ (`specs/07`) — принято осознанно: это цена Lucene-класса сегментации.

Больше ядру ничего не нужно. Каждая новая зависимость ядра проходит тот же
пробный прогон **до** внесения в Cargo.toml.

## HNSW: готовые крейты — проверены и отвергнуты

Все кандидаты **не собираются** под `wasm32v1-none`. Проверены и дефолтные
сборки, и `default-features = false`, и объявленные features каждого крейта
(списки сняты `cargo info` — у многих крейтов no_std включается именно
нестандартной комбинацией features, поэтому смотрели фичи, а не только дефолт):

| Крейт | Версия | Пробы | Результат | Причина |
|---|---|---|---|---|
| `instant-distance` | 0.6.1 | default; no-default (std-feature нет вовсе) | ❌ FAIL | безусловный `getrandom` → нет backend'а для wasm32v1-none |
| `hnsw_rs` | 0.3.4 | no-default (std-feature нет) | ❌ FAIL | требует std (prelude), rayon-ориентирован |
| `usearch` | 2.26.0 | no-default | ❌ FAIL | обёртка над C++, std |
| `hora` | 0.1.1 | no-default + его **собственные** `no_std`,`no_thread` | ❌ FAIL | даже родной no_std-режим тянет `rand → getrandom` («target is not supported»); заброшен (2021) |

**Вывод (подтверждает `04-indexes-recall.md`): HNSW реализуем сами внутри
`plugmem-core`**, поверх наших арен (level0 — фиксированные слоты, верхние
уровни — ChunkPool). Это и так было нужно для zero-copy снапшота графа и
flat-хвоста; отсутствие годного стороннего крейта снимает вопрос окончательно.

## Политика версий

- Все версии — в `[workspace.dependencies]`, крейты наследуют; точечные
  обновления — осознанным PR с прогоном полного CI (включая пробу
  `wasm32v1-none` и перф-гейты).
- Lock-файл коммитится (в workspace есть бинарники).
- MSRV фиксируем при первом релизе по фактическому минимуму (сейчас
  разработка на 1.96.0; `core::error::Error` требует ≥ 1.81).

## Методика проверки (воспроизводимая)

```sh
# пустой no_std крейт + кандидат, сборка под целевой таргет:
cargo new --lib probe && cd probe
printf '#![no_std]\n' > src/lib.rs
cargo add <crate> --no-default-features   # + нужные features
cargo build --target wasm32v1-none        # OK => годен для ядра
```

Проба выполняется в tmp-директории, в репозиторий не попадает; результат
(версия, конфиг, OK/FAIL, причина отказа) заносится в таблицы выше.
