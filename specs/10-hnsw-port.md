**Решение.**
- **Архитектурный донор — rust-cv/hnsw**: его скелет (плоские слои, межслойные
  ссылки, внешний Searcher, const-generic степени) почти дословно ложится на
  наши арены и философию zero-alloc. 550 строк ядра — обозримо для порта 1:1.
- **Алгоритмический донор — hnswlib-rs**: самая полная и свежая семантика;
  из неё берём эвристику отбора соседей (Алг. 4), корректную раннюю остановку
  и дефолты параметров. Код как таковой не портируем (7.5k строк std/rayon).
- **swapneel/hnsw-rust — отбрасываем**: учебная, ничего уникального не даёт.
  Клонировать больше ничего не нужно — всё необходимое уже на диске.

## Алгоритм HNSW — полное описание (как в статье Malkov & Yashunin, 2016)

Структура: многослойный граф соседства. Слой 0 содержит **все** элементы со
степенью ≤ M0; каждый следующий слой — разреженная «магистраль» (подмножество
предыдущего) со степенью ≤ M. Точка входа — единственный узел верхнего слоя.

1. **Назначение уровня** (Алг. 1, стр. 4): при вставке элементу назначается
   максимальный уровень `l = floor(-ln(U) · mL)`, U ~ uniform(0,1),
   `mL = 1/ln(M)` — геометрическое распределение: слой k содержит ~`M^-k`
   долю элементов.
2. **Вставка** (Алг. 1): жадный спуск от точки входа по слоям выше `l`
   (на каждом — поиск с ef=1); от слоя `min(l, top)` вниз до 0 — поиск с
   `ef = efConstruction`, на каждом слое новый узел соединяется с выбранными
   соседями (Алг. 3 или 4), связи двунаправленные; у переполнившихся соседей
   (степень > M/M0) список обрезается тем же отбором. Если `l > top`, элемент
   становится новой точкой входа.
3. **Поиск в слое** (Алг. 2): beam search: min-heap кандидатов по расстоянию +
   отсортированный пул `ef` лучших найденных + set посещённых; **остановка,
   когда ближайший кандидат дальше худшего из пула** — это ключ к
   сублинейности (у rust-cv этой остановки нет — чиним).
4. **Отбор соседей**:
   - Алг. 3 (простой): взять M ближайших. Так делает rust-cv.
   - **Алг. 4 (эвристика)**: кандидат берётся, только если он ближе к
     вставляемому, чем к любому уже выбранному соседу — даёт «растопыренные»
     рёбра, связывающие кластеры, а не M рёбер внутрь одного кластера.
     Критично для recall на кластеризованных данных (наш случай: память
     тематическими сгустками). Опции hnswlib: `extend_candidates` (добавить
     соседей кандидатов; для сильно кластеризованного), `keep_pruned`
     (добить неполный список отброшенными).
5. **k-NN запрос** (Алг. 5): спуск с ef=1 до слоя 1, на слое 0 — поиск с
   `ef_search ≥ k`, вернуть k лучших.

Параметры (дефолты из спеки 04, совпадают с рекомендациями hnswlib):
M=16, M0=32, efConstruction=200, ef_search=64, mL=1/ln(M).

## Наш порт: `plugmem-core::vector::hnsw`

Порт 1:1 скелета rust-cv с четырьмя системными заменами (каждая — следствие
наших спек, всё поверх `plugmem-arena`, ноль внешних зависимостей):

### Хранение (вместо Vec<Node> — арены; спека 01/04)

- **Слой 0**: DynArena, слот = `M0 × u32` соседей (128 Б при M0=32), индекс
  слота = vector-slot id факта. `!0` = пустая ячейка (как в доноре).
- **Верхние слои**: узлов ~`N/M^k` — ChunkPool-списки
  `(node_id u32, соседи M×u32, next_node u32)`; таблица слоёв — маленькая
  арена. Межслойные ссылки `zero_node`/`next_node` — схема rust-cv как есть.
- Точка входа + счётчики — в заголовке секции. Всё это — обычные секции
  снапшота: **zero-copy сохраняется**.

### Замены std-зависимостей (портабельность wasm32v1-none)

| У доноров | У нас | Почему |
|---|---|---|
| PRNG (`rand_core`, у rust-cv дет. seed; libm для ln) | **уровень = f(xxh3(fact_id))**: таблица порогов `T[k] = ⌊2⁶⁴·M^-k⌋` (предвычислена целочисленно), level = число порогов ниже хеша | ни PRNG-состояния, ни float, ни libm; **реплей журнала воспроизводит граф бит-в-бит** — уровень чистая функция id |
| `HashSet` посещённых (hashbrown+ahash → getrandom) | **generation-bitmap скретч**: `Vec<u16>` по dense id + счётчик эпохи; сброс = инкремент эпохи, O(1) | ноль аллокаций в поиске, ноль хеширования, нет getrandom |
| f32-метрика | i8-dot по квантованным слотам (i16→i32 аккумуляция), автовекторизуемый цикл (AVX2/simd128) | спека 04; расстояние целочисленное → сравнения точные, без NaN-капризов |
| LIFO-candidates rust-cv | классический min-heap (бинарная куча на скретч-буфере) + ранняя остановка Алг. 2 | меньше dist_evals — это наш гейт-счётчик |
| top-M отбор rust-cv | **Алг. 4 из hnswlib** (+ `keep_pruned` включён, `extend_candidates` — Config, default off) | recall на кластеризованной памяти |
| `usize`-индексы соседей (8 Б) | `u32` (потолок 1M — спека 00) | ×2 меньше трафика кэша графа |

### Интеграция с движком (спека 04, без изменений)

- Вставка в граф — **не** в `remember`: новые векторы падают во flat-хвост,
  `maintain()` вливает пачкой (bulk-insert дешевле и не рвёт бюджет remember).
- Удаления: tombstone-бит; поиск фильтрует; при >10% мёртвых `maintain`
  пересобирает граф (bulk-rebuild из живых — со свежими уровнями от тех же
  хешей — детерминирован).
- Поиск: HNSW по графу + линейный скан хвоста, слияние top-k; `allow`-bitmap
  (теги/время) применяется на кандидатах слоя 0.

### Псевдокод вставки (наши структуры)

```
insert_bulk(ids):                      # вызывается из maintain()
  for id in ids:
    l = level_of(xxh3(id))             # таблица порогов
    ep = entry; for k in top..l+1: ep = greedy_search(k, ep, q, ef=1)
    for k in min(l, top)..0:
      W = search_layer(k, ep, q, ef_construction)     # heap + gen-bitmap
      nbrs = select_heuristic(W, M_k)                 # Алг. 4, keep_pruned
      link_bidirectional(k, id, nbrs)                 # с обрезкой переполнений
      ep = W.nearest
    if l > top: entry = id; top = l
```

## План верификации порта

1. **Эталон корректности**: recall@10 ≥ 0.95 (ef=128) и ≥ 0.90 (ef=64) против
   brute-force f32 на testgen-корпусах 10k/100k (64 кластера) — CI-гейт.
2. **Паритет с донором**: нативный harness — тот же корпус в hnswlib-rs;
   наш recall при равных M/ef не хуже −1 п.п., dist_evals сопоставимы
   (фиксируется в bench-history).
3. **Детерминизм**: два построения графа с одного журнала → идентичные секции
   снапшота (побайтово).
4. **Счётчики**: dist_evals/запрос @100k, ef=64 ≤ потолок (заполняется
   измерением); zero-alloc поиска — счётчик-аллокатор.
5. Property: tombstone-фильтрация ≡ поиску по пересобранному графу без
   мёртвых (по множеству результатов).
